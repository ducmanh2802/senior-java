## 4. Đề xuất bổ sung nội dung ngân hàng

Đối chiếu số lượng câu hiện có do `node scripts/validate.js` in ra: Spring 27, SQL thực hành 14, REST API 14, Security 14, Microservices 28, System Design 21, AWS 22, AI/LLM 20, Docker/K8s/Linux/Git 14, Testing 16, English 51; tổng 479 câu. Spring, Microservices và System Design đã có độ phủ tương đối. Các nhóm xuất hiện trong JD nhưng còn mỏng tương đối là API, Security, DevOps/cloud-native và CI/CD. Đề nghị thêm 8 câu hỏi cụ thể:

1. **security (14 câu):** Khi dịch vụ dùng JWT/OAuth2, bạn thiết kế rotation/thu hồi token thế nào để giảm rủi ro token bị lộ mà không gọi introspection ở mọi request?
2. **security (14 câu):** Một API nội bộ cần service-to-service auth và phân quyền theo tenant; bạn chọn OAuth2 client credentials, mTLS hay kết hợp, và quản lý secret ra sao?
3. **api (14 câu):** Khi một API cần thay đổi contract nhưng có nhiều consumer deploy độc lập, bạn triển khai versioning và deprecation thế nào để tránh breaking change?
4. **api (14 câu):** Bạn thiết kế idempotency key cho endpoint thanh toán ra sao để xử lý retry/time-out mà không tạo giao dịch trùng?
5. **devops (14 câu):** Mô tả pipeline CI/CD cho Spring Boot trên Kubernetes có kiểm tra chất lượng, scan image, rollout canary và rollback tự động; tiêu chí dừng rollout là gì?
6. **devops (14 câu):** Pod Java liên tục OOMKilled sau khi tăng traffic; bạn phân biệt heap, native memory, container limit và cấu hình JVM thế nào trước khi tăng resource?
7. **aws (22 câu):** Một hệ thống Java cần xử lý event thanh toán bền vững; khi nào chọn Kafka/MSK, SQS hay EventBridge, và xử lý ordering/retry/DLQ thế nào?
8. **testing (16 câu):** Bạn xây dựng contract test cho producer/consumer Kafka và API giữa các team ra sao để deploy độc lập mà vẫn phát hiện incompatibility?

Đề xuất giữ trọng tâm câu hỏi ở trade-off, vận hành và failure mode, phù hợp cấp Senior/Lead; tránh thêm câu định nghĩa công nghệ.
