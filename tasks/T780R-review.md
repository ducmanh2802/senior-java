- `kotlin-020` (coroutine vs Virtual Thread): sửa câu "công lập đồng bộ có cấu trúc / con bao bị rò rỉ" (dịch sai, khó hiểu) → giải thích Structured concurrency rõ ràng (scope cha có vòng đời). Làm rõ Virtual Thread (JEP 444, Java 21, mount/unmount carrier thread, pinning với `synchronized` → dùng `ReentrantLock`) và coroutine (suspend, state machine, `Dispatchers.IO` cho blocking). Bảng trade-off đúng. Ví dụ Spring Boot 3 hợp lệ (`suspend fun` + `withContext(Dispatchers.IO)`). Số liệu benchmark đơn lẻ không được khẳng định vô căn cứ (giữ lời khuyên "đo p99/số luồng thực tế").
- `kotlin-021` (structured concurrency/cancellation): sửa tóm tắt dịch sai ("công lập… con bao bị rò rỉ") và giải thích "cooperative" dễ hiểu. Bổ sung cơ chế: `cancel()` chỉ đặt cờ, dừng ở suspend point hoặc `isActive/ensureActive()`. Khẳng định đúng: không nuốt `CancellationException`, không dùng `GlobalScope`, không `runBlocking` trong controller/filter, blocking call cần `Dispatchers.IO`. Ví dụ `coroutineScope`/`async-await` và `ensureActive()` đúng.
- `kotlin-022` (platform type/null safety): làm rõ `String!` (platform type), annotation `@Nullable/@NotNull` (JSR-305/JetBrains) và ghi chú thận trọng về hỗ trợ JSpecify tùy phiên bản Kotlin (không khẳng định bịa API cụ thể). Ví dụ `Map.get`/generic có thể chứa null đúng. Lưu ý `@field:` không áp dụng ở đây nhưng tuân thủ nullability boundary.
- `kotlin-023` (data class vs record vs JPA entity): nội dung kỹ thuật đã đúng hướng (data class equals/hashCode theo mọi property constructor chính, record immutable/final, Hibernate proxy cần open/subclass, entity identity theo id). Bổ sung giải thích copy shallow, proxy class khác (`is` đúng, so sánh `javaClass` sai), lazy access qua getter/property, `Persistable`/`isNew` khi id do ứng dụng gán (Spring Data sẽ `merge` nếu id khác null). Đúng cho Spring Boot 3.x/Hibernate 6/JDK 17+ (record accessors, JPA hydration hạn chế).
- `kotlin-024` (extension function): sửa/giữ cơ chế đúng (syntactic sugar → static method, resolve tĩnh theo kiểu khai báo, member ưu tiên). Bổ sung Java interop `@file:JvmName`, `@JvmName`, `@JvmOverloads`. Sửa lỗi chữ nước ngoài lẫn câu chuyện đời thực ("linguistic" giữ tiếng Anh thuật ngữ có giải thích ngữ cảnh; ví dụ đời thực viết tiếng Việt rõ). Giữ cảnh báo không truy cập private, không override.
- `kotlin-025` (Spring Boot + Kotlin plugins): sửa lỗi chữ nước ngoài "nửa caminho" → "giữa chừng" và làm rõ ví dụ đời thực. Nội dung kỹ thuật đúng: `kotlin-spring` (all-open) cho stereotype/`@Transactional/@Async/@Cacheable`, `kotlin-jpa` (no-arg) cho `@Entity/@Embeddable/@MappedSuperclass`; no-arg constructor không chạy initializer; `jackson-module-kotlin` cần có (Spring Boot auto-config nếu có dependency, tự tạo `ObjectMapper` thì đăng ký thủ công); `@field:NotBlank/@field:Min` cho Bean Validation đọc field/getter. Ghi chú `proxyBeanMethods=false` đúng ngữ cảnh `@Configuration`.
- `kotlin-026` (Flow vs Reactor/WebFlux): sửa lỗi gõ "vô hướngemit" → "phát (emit)" và giải thích thuật ngữ `collect`/cold flow/SSE/StateFlow conflation. Nội dung kỹ thuật đúng hướng: Flow cold, `SharedFlow/StateFlow` hot (StateFlow replay 1), Mono/Flux cold mặc định; Flow backpressure tự nhiên qua suspend/buffer/conflate/collectLatest; Reactor qua `request(n)`; bridge `flow.asFlux()`/`Publisher.asFlow()` và WebFlux adapt Flow. Lưu ý `ReactorContext/Dispatchers.Reactor` đúng hướng, không khẳng định ThreadLocal tự đồng bộ. Lỗi "vô hướngemit" và diễn đạt khó hiểu đã sửa.
